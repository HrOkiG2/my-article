『リーダブルコード』を読んで、すぐに実践できると感じたことを、備忘録としてまとめました。
可読性の高いコードを書きたい、PHPなどのプログラマーの方に向けた内容です。

## 結論

リーダブルコードには、**当たり前のことが書いてあります。**
ただ、その当たり前ができていないと感じたので、すぐに実践できることを残しておきます。

## プログラマーとして

### forのネスト

ループがネストしているときは、インデックスの名前を分かりやすく定義します。
ループする変数の接頭辞を、インデックスの接頭辞にすると、インデックスを使うのが楽になります。
(ループをネストしないコードが書ければ、それが一番よいです。)

```php
$users = [
    // 複数要素
];
$entry_points = [
    // 複数要素
];

for ($u_i = 0; $u_i < count($users); $u_i++) {
    for ($e_i = 0; $e_i < count($entry_points); $e_i++) {
        // 処理: $users[$u_i] と $entry_points[$e_i]
    }
}
```

## コメント

### コードに指摘を入れる場合

自分が書いたコードでも、他人のコードでも、何か気になったときは、次のようにコメントを残したいです。
特に、Gitのコメントにも使えそうです。

| 接頭辞 | 内容 | 備考 |
| --- | --- | --- |
| `TODO:` | やるべきこと。あとで手を付けます。 | 複数案件を抱えているときに、役立ちそうです。 |
| `FIX:` | 既知の不具合があるコードです。 | 修正すべき内容です。 |
| `HACK:` | あまりきれいではない解決策です。 | 「改修の余地があるよ」と伝えるときに使います。 |
| `DANGER:` / `IMPORTANT:` | 危険な箇所です。 | リーダブルコードには「XXX:」と書かれていますが、自分なりに変えました。 |

### クラスやメソッドは、ひと目で分かるように

クラスやメソッドの処理が、すぐに理解できるように、処理内容をコメントします。
パターンは、次のとおりです。

* **実例をコメントする**: 「XXXを〇〇〇して、△△△という形式に変更」のように書きます。
* **処理をブロックごとに分けて、コメントする**: 大きいメソッドは、適切なタイミングでコメントを入れます。

### 問題になりそうな箇所は、先に明示する

これは大事だと思うので、例を書きます。
`insert` 関数と `delete` 関数があって、`insert` の前に `delete` を実行する処理があるとします。

```php
class DB {
    public function insert($data) {
        DB::delete();
        // ...
    }

    public function delete() {
    }
}
```

`insert` の中で `delete` を呼んでいます。
もし `delete` が複雑な処理で、10秒かかるとしたら、`insert` 自体が10秒以上かかります。
詳細を知らないメンバーが `insert` を呼ぶと、想定外の結果になる危険があるので、次のようにコメントを残します。

```php
class DB {
    public function insert($data) {
        DB::delete();
        // ...
    }

    // 注意: 実行時間が10秒以上かかる
    public function delete() {
    }
}
```

## まとめ

* ループのネストでは、インデックスの名前を分かりやすくします。
* 縦にそろえると、視覚的に読みやすくなります。
* `TODO:`、`FIX:`、`HACK:` などの接頭辞で、コメントの意図を伝えます。
* 問題になりそうな箇所は、先にコメントで明示します。
