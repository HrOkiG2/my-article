EC2の奥の深い部分として、インスタンスタイプ、Dedicated Hosts/Instances、プレースメントグループを整理しました。
EC2を使っているものの、種類や配置の違いを理解しきれていない方に向けた内容です。

## 結論

* インスタンスタイプは、用途(汎用、コンピューティング、メモリ、GPU、ストレージ)で選びます。
* 物理サーバーを専有したいときは、Dedicated HostsかDedicated Instancesを使います。
* 障害に強くしたいときは、プレースメントグループで配置を制御します。

## インスタンスタイプ

ファミリーは、大きく5種類に分けられます。

| 種類 | 特徴 | ファミリー |
| --- | --- | --- |
| 汎用 | バランスが取れている | T、M、A、Mac |
| コンピューティング最適化 | 計算性能が高い | C |
| メモリ最適化 | メモリ量が多くて高速 | R、X、z |
| 高速コンピューティング | GPUを搭載 | P、G、F、Inf |
| ストレージ最適化 | ストレージアクセスが速い | I、D、H |

参考: [EC2インスタンスタイプの意味と特徴の覚え方(Zenn)](https://zenn.dev/matsu7089/articles/meaning-of-ec2-instance-types)

| ファミリー | 特徴 | ユースケース |
| --- | --- | --- |
| **T系**(汎用、バースト可能) | コスト効率が高い汎用。必要に応じてCPU性能がバーストします。 | 小規模Webサーバー、テスト環境、低負荷のアプリ |
| **M系**(汎用) | CPU、メモリ、ストレージのバランスがよく、多様なワークロードに対応します。 | 中規模アプリ、バックエンドサーバー、データベース |
| **C系**(コンピューティング最適化) | 高いCPU性能で、計算集約型に最適です。 | 高性能Webサーバー、科学計算、機械学習 |
| **R系**(メモリ最適化) | 大量のメモリで、メモリ集約型に最適です。 | インメモリDB、大規模DB、キャッシュ |
| **I系**(ストレージ最適化) | 高いディスクI/Oと、ローカルNVMeストレージを使えます。 | NoSQL、分散ファイルシステム、ログ処理 |
| **G系**(GPU搭載) | GPUで並列処理性能が高いです。 | 機械学習、3Dレンダリング、動画エンコード |
| **H系**(ハイメモリ) | 非常に大容量のメモリを搭載します。 | エンタープライズアプリ、超大規模DB、高度な分析 |

## Dedicated HostsとDedicated Instances

### Dedicated Hosts

* **物理サーバー全体を管理**する権限があり、ホスト単位で細かく制御できます。
* **インスタンスの配置を制御**でき、どのホストにどのEC2を置くか決められます。
* **ライセンスの持ち込み(BYOL)**ができます。たとえば、Windows ServerやSQL Serverの専用ライセンスを持ち込む場合に最適です。
* ホスト単位でCPUコアやRAMの使用状況を追跡できるので、監査やコンプライアンス要件がある場合に有効です。
* ホストの長期契約が前提で、**ホスト単位で課金**されます(動いていないインスタンスがあっても、料金がかかります)。

**ユースケース**

* ライセンス制約が厳しいソフトウェアを使う場合
* 特定の物理ホスト上での稼働が必要なアプリ
* ホストとインスタンスの配置の柔軟性が必要なワークロード

### Dedicated Instances

* AWSが提供する物理サーバー上で、**特定のユーザー専用**のEC2を動かします。
* 物理ホストの管理はAWSが行います。
* どの物理ホストに置くかは、指定できません(AWSが自動管理)。
* **インスタンス単位で課金**されます。
* ライセンスの持ち込みができる場合もありますが、Dedicated Hostsほど柔軟ではありません。

**ユースケース**

* 他の顧客との物理リソースの分離だけが必要な場合
* インスタンス単位でコスト管理したい場合
* ホストの詳細管理は不要で、AWSに任せたい場合

### デフォルトのインスタンス

デフォルトは**共有インスタンス(Shared Instances)**で、複数の顧客のインスタンスが同じ物理ホストで動きます。
論理的に隔離されているので、セキュリティや性能に問題はありませんが、物理的には分離されていません。

### 違いの早見表

| | Dedicated Hosts | Dedicated Instances |
| --- | --- | --- |
| 制御レベル | ホスト単位の詳細な管理 | インスタンス単位の管理 |
| 配置制御 | どのホストにどのインスタンスを置くか指定できます | 自動で割り当てられます |
| 課金方法 | ホスト単位 | インスタンス単位 |
| ライセンス持ち込み(BYOL) | 柔軟に対応 | 一部対応 |
| 管理の難易度 | 高い(ユーザーがホストを管理) | 低い(AWSがホストを管理) |

## プレースメントグループ

### クラスタープレースメントグループ

* グループ内のインスタンスを、物理的に近い距離に配置します。
* **メリット**: 近くに配置されるので、遅延が少ないです。
* **デメリット**: クラスターのあるAZに障害が起きると、すべて影響を受けます。障害に弱いです。

### パーティションプレースメントグループ

* パーティションという論理グループに分けて配置します。
* 各パーティションに、1つ以上のEC2が所属します。
* 各パーティションに、1つのラックが対応します。ラックには、独立した電源とネットワークがあります。
* 異なるAZにEC2を配置できます。
* **メリット**: ラックはパーティション間で共有されないので、ハードウェア障害に強いです。

### スプレッドプレースメントグループ

* 異なるハードウェアにEC2を配置します。
* ハードウェアとEC2は、1対1の関係です。
* 異なるAZにEC2を配置できます。
* **メリット**: ハードウェアを共有しないので、ハードウェア関連の障害に強いです。

## まとめ

* インスタンスタイプは、用途(汎用、コンピューティング、メモリ、GPU、ストレージ)で選びます。
* Dedicated Hostsは「ホスト単位の管理」、Dedicated Instancesは「インスタンス単位の専有」です。
* プレースメントグループは、遅延重視ならクラスター、障害対策重視ならパーティションかスプレッドです。
