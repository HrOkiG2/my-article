AWSのVPCまわりで混乱しやすい、ネットワークACLとセキュリティグループ、NATゲートウェイとNATインスタンス、VPCのリソースをまとめました。
VPCの設計や、AWS資格の勉強で、違いを整理したい方に向けた内容です。

## 結論

VPCは、似た機能が多くて難しいですが、「どの単位で効くか」「ステートフルかどうか」「マネージドかどうか」で整理すると見分けやすくなります。

## ネットワークACLとセキュリティグループ

| 項目 | ネットワークACL(NACL) | セキュリティグループ |
| --- | --- | --- |
| 適用範囲 | サブネット単位 | インスタンス単位 |
| ルールの処理順 | 番号順に評価(最初に一致したルールが適用) | 全ルールを評価して、許可されるものだけが適用 |
| 許可・拒否の指定 | 許可と拒否の両方を指定できます | 許可ルールのみ指定できます |
| ステートフル/ステートレス | ステートレス(応答トラフィックもルールで明示的に許可が必要) | ステートフル(インバウンドを許可すると、応答は自動で許可) |
| デフォルトの動作 | すべて許可(デフォルトNACLの場合) | インバウンドはすべて拒否(デフォルトの場合) |
| ユースケース | 複数のインスタンスに、一貫したトラフィック制御をしたい場合 | インスタンスごとに、細かく制御したい場合 |
| 推奨される用途 | サブネットレベルのアクセス制御 | アプリケーションレベルのアクセス制御 |

:::message
ルールの上限数は、クォータとして変更できるため、最新の値はAWSのドキュメントで確認してください。
:::

## NATゲートウェイとNATインスタンス

| 項目 | NATゲートウェイ | NATインスタンス |
| --- | --- | --- |
| 設定と管理 | フルマネージド。AWSが自動でスケーリングと冗長性を提供します。 | EC2を手動で立てて管理します。スケーリングや冗長化は、ユーザーが設定します。 |
| 可用性 | 高可用性(単一AZ、またはマルチAZ対応) | 冗長化は手動(自動フェイルオーバーなし) |
| スケーラビリティ | 自動でスケールします。 | インスタンスのサイズや数を、手動で調整します。 |
| 料金 | 使用時間とトラフィックで課金されます。基本的に高コストです。 | インスタンスのサイズと実行時間で課金されます。小規模なら安く済みます。 |
| スループット | 最大45Gbpsです。 | インスタンスの種類に依存します。 |
| セキュリティグループ | 設定できません(NACLで制御します)。 | 設定できます。 |
| 運用の複雑さ | AWSが管理するので、負担が少ないです。 | 監視、メンテナンスが必要です。 |
| ユースケース | 高可用性とスケーラビリティが重要な環境 | コストを抑えたい小規模環境やテスト環境 |

## ルートテーブル

VPC内のルーティングを行います。

* 送信先に当てはまらない通信は、デフォルトの `0.0.0.0/0` に流れます。
* 送信先に一致した通信は、そのターゲットにルーティングされます。

## VPC内で使われるリソース・機能

### VPCエンドポイント

S3やDynamoDBなど、VPCの外にあるAWSサービスには、通常、インターネットゲートウェイを経由してアクセスします。

VPCエンドポイントは、**プライベートサブネット内のAWSリソースが、インターネットゲートウェイを経由せずに、VPC外のAWSサービスへアクセスできるようにする機能**です。
方法は2つあります。

* **ゲートウェイ型**: ルートテーブルにVPCエンドポイントを指定してルーティングします。イメージは「VPCに専用の穴を開ける」です。
* **PrivateLink(インターフェース型)**: AWSサービスに接続したいリソースがあるサブネットに、プライベートIPを持つENIを作って、ENIとサービスをリンクします。イメージは「直リンク」です。

### VPCピアリング

VPC同士を結びつける機能です。

* **異なるアカウント間のVPC接続**: 別のAWSアカウントのVPCとも、ピアリングできます。
* **リージョン間の接続**: 異なるリージョンのVPC間でも、安全な通信ができます。

### Egress-Onlyインターネットゲートウェイ

IPv6専用の**アウトバウンド通信**を提供するゲートウェイです。
IPv6を使うVPCで、「インターネットへの発信は許可して、受信はブロックしたい」ときに使います。
NATゲートウェイのIPv6版と考えると分かりやすいです。

### AWS Transit Gateway

複数のVPCやオンプレミスのネットワークを、**中央のハブ**で接続するサービスです。
各VPCやVPNをTransit Gatewayにつなぐと、個別にルーティングを設定せずに、効率よく相互接続できます。

## まとめ

* NACLは「サブネット単位・ステートレス」、セキュリティグループは「インスタンス単位・ステートフル」です。
* NATゲートウェイは、マネージドで高可用、NATインスタンスは、安いけれど運用が必要です。
* VPCエンドポイントで、インターネットを経由せず、AWSサービスにアクセスできます。
* VPC同士の接続は、ピアリングかTransit Gatewayを使います。
