Gitの基本的な考え方と、よく使うコマンドをまとめました。
Gitを使い始めたばかりの方や、チーム開発の流れを知りたい方に向けた内容です。

## 結論

Gitの基本は、「ローカルで作業 → `add` → `commit` → `push` → マージ」の流れです。
ワークツリー、ステージ、リモートリポジトリの3つの場所を意識すると、理解しやすくなります。

## GitとGitHubでできること

| | できること |
| --- | --- |
| Git | バージョン管理、前の状態に戻す、チーム開発 |
| GitHub | コードの共有、コードレビュー、OSSへの参加 |

## 考え方

「リモート」と「ローカル」の2つの環境があります。
リモートでは、チームのみんなが開発したコードをまとめた、デフォルトブランチ(`main` など)を軸にして、各自が機能を実装していきます。

流れは、次のとおりです。

1. 自分のPC(ローカル環境)に、プロジェクトのソースを取得します。新しくローカルブランチを作って、そのブランチで作業します。
2. 機能を実装します。
3. 実装内容を、リモートリポジトリに `push` します。
4. 実装内容を、レビューしてもらうために申請します(プルリクエスト)。
5. デフォルトブランチに `merge` します(実装したコードを統合します)。

## 基本コマンド

### 初期化

新しくプロジェクトに参加したら、ローカルにプロジェクト用のディレクトリを作ります。
ローカル環境を初期化すると、「**これからこのディレクトリで作業します**」と宣言できて、Gitで管理するために必要なものが準備されます。

```bash
git init
```

:::message
すでにあるリモートリポジトリで作業する場合は、`git init` ではなく、`git clone <URL>` で取得します。
:::

### 記録

リモートリポジトリに登録するには、次の3段階を踏みます。

1. **ワークツリー**: ローカル環境
2. **ステージ**: 中間の場所
3. **リモートリポジトリ**: リモート環境

**ワークツリー → ステージ**に変更を登録するのは、`git add` です。
**ステージ → ローカルリポジトリ**に記録するのは、`git commit` です。

```bash
# 全ファイル
git add .

# ファイルを指定
git add ファイル名.php

# コミット(変更内容をコメントに書く)
git commit -m "コミットメッセージ(変更内容を記載)"
```

**ローカルリポジトリ → リモート環境**に反映するのは、`git push` です。

```bash
git push origin ブランチ名
```

:::message
* `add`: 「次のコミットに含めるよ」と、ステージに載せます。
* `commit`: ステージの内容を、リポジトリに記録します。
:::

### 確認

```bash
# ワークツリーとステージの差分
git diff

# ステージとリポジトリの差分
git diff --staged

# 状態の確認
git status
```

### 履歴の確認

変更内容を見るコマンドです。

```bash
git log
```

### 変更の修正

```bash
# ワークツリーの変更を取り消す
git restore ファイル名

# ステージに上げた変更を、ワークツリーに戻す
git restore --staged ファイル名
```

## 現場での使われ方

デフォルトブランチに新機能がマージされたら、次の対応をします。

1. リモートリポジトリのデフォルトブランチを `pull` します。
2. 前回の作業用ブランチを削除します。
3. 新しい作業用のローカルブランチを作ります。

この手順で、**最新の状態をもとに、作業を始められます。**

## まとめ

* Gitはバージョン管理、GitHubはコードの共有やレビューができるサービスです。
* `add` → `commit` → `push` の流れで、変更をリモートに反映します。
* `status`、`diff`、`log` で、状態や履歴を確認できます。
* 機能を作るたびに、デフォルトブランチを最新にして、新しいブランチで作業しましょう。
