UFWとWAFの違いを、サーバー構築の視点で整理しました。
サーバー構築を任されて、ufwとwafの違いがピンとこなかった方に向けた内容です。

## 結論

* **UFW**は、Linuxのファイアウォール設定を簡単にするツールで、**ポート単位**の制御をします。
* **WAF**は、**Webアプリケーション**への攻撃(SQLインジェクション、XSSなど)を防ぐ、専用のセキュリティツールです。
* 用途が違うので、**両方を組み合わせて**使います。

違いを分からないまま、ノリで進めると、恥をかくので、先に学んでおくことをおすすめします。

## UFW(Uncomplicated Firewall)とは

Linuxのシステムで、ファイアウォールを設定するためのツールです。
`iptables` という、より高度なファイアウォール設定を簡略化したもので、コマンドラインで簡単に設定できます。

**主な特徴**

* **ポートベースのファイアウォール設定**ができます。
  * 特定のポートへのアクセスを制御します。
  * IPアドレス、サブネット、アプリケーションなどの指定もできます。
* **シンプルな構文**です。
  * システム全体のファイアウォールとして機能します。
  * ネットワークトラフィックを制御します。
  * Webアプリケーションのセキュリティには、直接関係しません。

### 使用例

```bash
# HTTPSのポートを開放
sudo ufw allow 443

# MySQLのポートを開放
sudo ufw allow 3306

# SSHのポートを閉鎖
sudo ufw deny 22
```

:::message alert
**SSHのポートの開閉には、注意してください。**
`ufw` でSSHのポートを閉じると、当然ですが、SSHでサーバーに接続できなくなります。
私は、コントロールパネルから操作する権限のないアカウントで作業していて、構築作業が何もできない状況になりました。
サーバー管理者に申請する時間がなく、サーバーを削除して、最初から構築し直しました。
SSH周りの設定は、慎重に進めましょう。
:::

## WAF(Web Application Firewall)とは

Webアプリケーションのセキュリティを強化するための、セキュリティツールです。
Webトラフィックに特定のルールを適用して、Webアプリへの攻撃(SQLインジェクション、XSSなど)から保護します。

**主な特徴**

* **Webアプリへのトラフィックのフィルタリング**
  * HTTPとHTTPSのトラフィックを対象に、不正なリクエストや攻撃を検出して、遮断します。
  * **パターンマッチング**: 特定の攻撃パターンや脆弱性に対する、シグネチャやルールで、攻撃を検出します。
  * **ロギングと監視**: 攻撃の試みをログに記録して、セキュリティ担当者が監視、対応できるようにします。

WAFは、WebサーバーとWebアプリの間に配置されて、攻撃をブロックして、アプリを保護します。

### WAFは販売されている

今回学ぶまでは、WAFが防御する内容が、SQLインジェクションやXSSだったので、自分でプログラムを書いて防御するものだと思っていました。
(自分で書くべきプログラムの総称だと思っていました。)
ですが、深掘りすると、WAFは多くの製品が販売されていて、運用を楽にするために、多くの企業が導入していると分かりました。
独自ルールを追加できる、AWS WAFも、そのうち勉強しないといけません。

## 用途の異なるセキュリティツール

| ツール | 役割 | 対象 |
| --- | --- | --- |
| UFW | システムのファイアウォール設定を、簡単に行う | ポート、IPアドレス |
| WAF | Webアプリケーションのセキュリティを向上させる | HTTP/HTTPSのリクエストの中身 |

## まとめ

* UFWは、ポート単位でサーバーへのアクセスを制御します。
* WAFは、Webアプリへの攻撃を、リクエストの中身から検出して防ぎます。
* 用途が違うので、両方を使って、多層で守りましょう。
* SSHのポートを閉じるときは、接続できなくなる点に注意してください。
