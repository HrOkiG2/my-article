PHPアプリケーションのDockerイメージを、マルチステージビルドで軽量化する方法をまとめました。
イメージが大きくなって困っているPHP開発者・DevOps担当の方に向けた内容です。

## 結論

マルチステージビルドを使って、「ビルド用のステージ」と「実行用のステージ」を分けましょう。
最終イメージには、実行に必要なものだけを入れられるので、サイズが小さくなり、セキュリティも上がります。

## マルチステージビルドとは

1つの `Dockerfile` の中に、複数の `FROM`(ステージ)を書き、**最終イメージには、デプロイに必要なファイルだけをコピーする**手法です。

PHPのイメージにComposerやコンパイラなどのビルド用ツールまで入れると、イメージが大きくなり、セキュリティリスクも増えます。
それを解決するのが、マルチステージビルドです。

### 役割分担

**ビルドステージ(Build Stage)**

* 目的: アプリケーションのビルドと、依存関係の解決です。
* 使うイメージ: 大きめのイメージ(`composer:latest`、`php:8.3-fpm` など)です。
* 作業: Composerによる依存パッケージのインストール、フロントエンドのコンパイル、テストの実行などです。
* 特徴: このステージは、最終的なデプロイには使いません。

**最終ステージ(Final Stage)**

* 目的: アプリケーションの実行環境の構築です。
* 使うイメージ: 軽量なイメージ(`php:8.3-fpm-alpine`、`distroless` など)です。
* 作業: ビルドステージで作った**成果物**(`vendor` ディレクトリやPHPコードなど)だけをコピーします。

### メリット

* **イメージサイズを大きく削減**: ビルドツールやキャッシュ、開発用の依存関係が、最終イメージから外れます。
* **セキュリティの向上**: 最終イメージが最小限の構成になるので、攻撃される範囲が小さくなります。
* **プル時間の短縮**: 軽量なイメージなので、プルにかかる時間が短くなります。

## PHPアプリケーションでの例

PHPの典型的なマルチステージビルドは、**Composerによる依存関係の解決を分離**することがポイントです。

### Dockerfile

Composerで依存関係を解決するステージと、それを使って実行する最小限のステージに分けています。

```dockerfile
# =============================================
# ステージ1: build_stage (依存関係の解決)
# =============================================
FROM composer:latest AS build_stage
WORKDIR /app

# 先に依存関係ファイルだけをコピー(キャッシュ効率化のため)
COPY composer.json composer.lock ./

# 本番環境用に最適化してインストール
# --no-dev: 開発用パッケージを除外
# --optimize-autoloader: オートローダーを最適化して高速化
RUN composer install \
    --no-dev \
    --no-interaction \
    --optimize-autoloader

# =============================================
# ステージ2: final_stage (最小限の実行環境)
# =============================================
# 軽量なAlpine LinuxベースのPHP-FPMイメージを使用
FROM php:8.3-fpm-alpine AS final_stage

# セキュリティ: 実行用の非特権ユーザーを作成
RUN adduser -D appuser
USER appuser

WORKDIR /var/www/html

# ステージ1から vendor ディレクトリのみをコピー
# --chown で所有権を同時に変更するのがポイント
COPY --from=build_stage --chown=appuser:appuser /app/vendor ./vendor

# アプリケーションのソースコードをコピー
COPY --chown=appuser:appuser . .

# PHP-FPMを起動
EXPOSE 9000
CMD ["php-fpm"]
```

### 実行手順

1. 上の `Dockerfile` を、プロジェクトのルートに置きます。
2. 通常どおり `docker build` を実行します。Dockerが自動で、マルチステージビルドを処理してくれます。

```bash
docker build -t my-php-app:prod .
```

## PHPでのポイント

1. **公式のcomposerイメージをビルダーにする**: Composerをインストールする手間が省けるので、いちばん効率的です。
2. **`--no-dev`**: テストフレームワークなど、開発時だけ必要なパッケージは、最終イメージに含めません。
3. **非特権ユーザーで実行する**: 最終ステージでは、`root` 権限を使わず、非特権ユーザー(上の例では `appuser`)でアプリを動かしましょう。低いポート番号を使うのに制約が出ますが、セキュリティは大きく上がります。
4. **`COPY --from` を活用する**: Composerの大きなキャッシュやビルドツールを最終イメージから除いて、必要な `vendor` だけをきれいにコピーできます。

:::message
`php:8.3-fpm-alpine` には、`pdo_mysql` など、アプリが必要とするPHP拡張が入っていません。
必要な拡張は、`docker-php-ext-install` などで、最終ステージに追加してください。
:::

## まとめ

* マルチステージビルドは、ビルド用と実行用のステージを分ける手法です。
* 最終イメージには、`vendor` などの成果物だけをコピーします。
* イメージサイズの削減と、セキュリティの向上が見込めます。
* 軽量で安全なPHPのコンテナイメージを作るなら、ぜひ導入してみてください。
