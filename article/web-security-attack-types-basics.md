Web開発で押さえておきたい、主要な攻撃タイプと、その対策をまとめました。
Webアプリケーションを開発する方が、最低限の攻撃手法と対策を、一覧で確認するための内容です。

## 結論

攻撃の種類は多いですが、対策の基本は共通しています。
**入力の検証とサニタイズ、権限の最小化、セキュリティヘッダーの設定**を、徹底しましょう。

## 一覧

| 攻撃 | 概要 | 主な対策 |
| --- | --- | --- |
| ブルートフォース | 認証情報を総当たりで試す | 強力なパスワード、ロックアウト、二要素認証 |
| SQLインジェクション | 不正なSQLを注入する | プリペアドステートメント、ORM、入力検証 |
| XSS | 悪意のあるスクリプトを注入する | サニタイズ、CSP、Cookie属性 |
| ディレクトリトラバーサル | `../` で上位階層のファイルにアクセスする | 入力検証、権限の制限、ホワイトリスト |
| URLエンコード攻撃 | エンコードした入力で、検証をすり抜ける | デコード後の検証、サニタイズ |
| CSRF | ユーザーに意図しないリクエストを送らせる | CSRFトークン、SameSite属性 |
| セッションハイジャック | セッションIDを盗んで、なりすます | ID再生成、HttpOnly/Secure |
| Hostヘッダフォージェリ | Hostヘッダーを偽造する | Hostの検証、ホワイトリスト |
| クリックジャッキング | 透明なフレームで、クリックさせる | X-Frame-Options、CSP |
| DDoS | 大量のトラフィックで、サービスを妨害する | フィルタリング、DDoS対策サービス |
| LDAPインジェクション | LDAPクエリに不正な入力を挿入する | エスケープ、ホワイトリスト |
| コマンドインジェクション | 任意のOSコマンドを実行させる | 外部コマンドを避ける、入力検証 |
| ファイルインクルード | 不正なファイルを読み込ませる | 入力検証、ローカルファイルのみに制限 |
| HTTPヘッダインジェクション | 改行でヘッダーを注入する | 改行文字のサニタイズ |

## ブルートフォースアタック

ユーザー名やパスワードなどの認証データを、**総当たり**で推測して、不正にアクセスしようとする攻撃です。
攻撃者は、一般的なパスワードや辞書に載っている単語を使うことが多く、弱いパスワードのアカウントは、特に危険です。

**対策**

* **強力なパスワードポリシー**: 複雑で、予測しにくいパスワードを義務付けます。
* **アカウントロックアウト**: 一定回数以上ログインに失敗したら、一時的にロックします。
* **二要素認証**: パスワードに加えて、別の認証(SMSのコードなど)を使います。

## SQLインジェクション

攻撃者が、不正なSQLを、入力フォームなどに注入して、バックエンドのDBを操作する攻撃です。
機密情報の漏えい、データの改ざん、不正な操作につながります。

**対策**

* **パラメータ化されたクエリ**: ユーザー入力を、パラメータとして扱います。
* **ORMの利用**: SQLインジェクションのリスクを減らします。
* **入力検証**: ユーザーの入力を厳格に検証して、不正なデータを除外します。

## クロスサイトスクリプティング(XSS)

悪意のあるスクリプトをWebページに注入して、ほかのユーザーのブラウザで実行させる攻撃です。
セッション情報の盗難や、不正な操作につながります。

**XSS攻撃の例**

```
## 悪意のあるリンクを注入される
http://example.com/search?query=<script>alert('XSS')</script>

## 悪意のある値を入力される
こんにちは! <script>alert('XSS');</script>
```

**対策**

* **入力のサニタイズ**: 入力を適切にクリーニングして、スクリプトの実行を防ぎます。
* **Content Security Policy(CSP)**: 信頼できるソースのスクリプトだけを許可します。(JSの制御ができるので、おすすめです。)
* **セキュアなCookie**: `HttpOnly` や `Secure` 属性で、Cookieの盗難を防ぎます。

## ディレクトリトラバーサル

`../` などを使って、アプリケーションのルートを越えて、サーバー上のファイルにアクセスする攻撃です。
たとえば、Ubuntuでは `/var/www/domain.com` にソースを置くことが多く、`../../` で、上の階層(`www` や `var`)のデータを盗まれるおそれがあります。

**対策**

* **入力の検証とサニタイズ**: ファイル名やパスの入力を、厳密に検証します。
* **アクセス権限の制限**: Webサーバーの権限を、最小限にします。
* **ホワイトリスト**: あらかじめ許可したファイルだけに、アクセスできるようにします。

## URLエンコード攻撃

Webアプリが、URLエンコードされた入力を、適切に処理しないことを利用した攻撃です。
XSSやSQLインジェクションなど、ほかの攻撃と組み合わせて使われます。

```
オリジナル:           <script>alert('XSS');</script>
URLエンコード後:      %3Cscript%3Ealert%28%27XSS%27%29%3B%3C%2Fscript%3E
```

**対策**

* **デコードと検証**: エンコードされた入力をデコードして、厳格に検証します。
* **サニタイズ**: サーバーに渡す前に、悪意のあるコードを除去します。
* **ほかの攻撃への対策の強化**: XSSやSQLインジェクションへの対策が、そのまま役立ちます。

## クロスサイトリクエストフォージェリ(CSRF)

ログイン済みのユーザーのブラウザを使って、ユーザーの知らないうちに、悪意のある操作をさせる攻撃です。
パスワードの変更、送金、メッセージの送信などが行われるおそれがあります。

**対策**

* **CSRFトークン**: セッションごとに一意のトークンを発行して、リクエストに含め、サーバー側で検証します。
* **SameSite属性**: `SameSite=Lax` や `Strict` で、異なるオリジンへのCookie送信を防ぎます。
* **リファラーの検証**: リクエストが、信頼できる送信元かを確認します。
* **自動ログアウト**: 操作がないときに、自動でログアウトします。
* **CORSポリシー**: 異なるオリジンからのリクエストを、厳格に制御します。

## セッションハイジャック

ログイン後のセッションIDを盗んで、ログイン者になりすます攻撃です。
不正送金や不正購入などが可能になります。

**対策**

* セッションIDを、URLや `hidden` に含めません。
* ログイン後に、`session_regenerate_id()` でIDを書き換えます。
* Cookieに `HttpOnly` と `Secure` を付けます。

```php
echo session_id();            // ① 書き換え前
session_regenerate_id(true);  // セッションIDを書き換え
echo session_id();            // ② 書き換え後
```

```apache
# Apacheでの設定
Header edit Set-Cookie ^(.*)$ $1;HttpOnly;Secure
```

```ini
; php.ini での設定
session.cookie_httponly = 1
session.cookie_secure = 1
```

## Hostヘッダフォージェリ

攻撃者が、HTTPリクエストのHostヘッダーを偽造して、Webアプリを誤ったサイトに向けさせる攻撃です。
パスワードリセット機能を悪用して、リダイレクトやメールヘッダーの注入などが行われます。

**対策**

* **Hostヘッダーの検証**: 受け取ったHostが、期待するものかを検証して、不正なら拒否します。
* **ホワイトリスト**: 信頼できるHost名だけを受け入れます。
* **安全なリダイレクト**: ヘッダーの内容に基づかず、あらかじめ定義したURLを使います。

## クリックジャッキング

透明なフレームなどを使って、ユーザーに、知らないうちにボタンやリンクをクリックさせる攻撃です。

**対策**

* **X-Frame-Optionsヘッダー**: ページがほかのフレームで表示されるのを防ぎます。
* **CSPの `frame-ancestors`**: ページが埋め込まれるのを制限します。
* **JavaScriptでの防御**: フレーム内での表示を検出して防ぎます。

## DDoS攻撃

膨大なトラフィックを、サーバーやネットワークに送り込んで、サービスを使えなくする攻撃です。

**対策**

* **トラフィックの監視とフィルタリング**: 異常なパターンを検出して、フィルタリングします。
* **クラウドのDDoS保護サービス**: 専門のサービスで、攻撃を軽減します。
* **帯域幅の増加**: 一定量の攻撃トラフィックを、吸収できるようにします。
* **レートリミット**: リクエスト数を制限して、負荷を軽減します。

## LDAPインジェクション

LDAPクエリに不正な入力を挿入して、認証やディレクトリ情報を不正に取得する攻撃です。
(LDAPクエリとは、LDAP: Lightweight Directory Access Protocolで、ディレクトリサービスから情報を検索・操作するための命令です。)

**対策**

* 入力のサニタイズとエスケープ
* ホワイトリストによる入力検証
* アクセス権限の最小化

## コマンドインジェクション

Webアプリを通じて、サーバー上で任意のシステムコマンドを実行させる攻撃です。
ユーザーの入力を適切に処理しないと発生し、システムレベルの操作ができてしまうので、とても危険です。

**対策**

* **外部コマンドの実行を避ける**: アプリレベルの機能で代替します。
* **入力の厳格な検証**: コマンドに渡す前に、検証します。
* **最小限の権限での実行**

## ファイルインクルード

外部または内部のファイルを、不正に読み込ませる攻撃です。
サーバー上のファイルへのアクセスや、リモートファイルの実行が可能になります。

**対策**

* **入力検証**: インクルードするファイルの入力を、厳密に検証します。
* **ローカルファイルのみに制限**: リモートファイルのインクルードを禁止します。
* **アクセス権限の制御**: アクセスできるファイルを、制限します。

## HTTPヘッダインジェクション

HTTPレスポンスヘッダーに、不正な内容を注入する攻撃です。
改行文字を含む入力で、新たなヘッダーを注入したり、既存のヘッダーを改変したりします。
XSS、リダイレクト攻撃、セッションハイジャックなどにつながることがあります。

**対策**

* **入力の検証とサニタイズ**: 改行文字や制御文字を徹底してサニタイズします。
* **セキュリティヘッダーの設定**: CSPやX-Frame-Optionsなどを設定します。
* **フレームワークやライブラリの活用**: 自動で、多くの対策が適用されます。

## まとめ

* 攻撃の種類は多いですが、「入力の検証とサニタイズ」が基本です。
* セッションやCookie、セキュリティヘッダーの設定も、あわせて行いましょう。
* 権限は最小限にして、フレームワークの機能を活用しましょう。
