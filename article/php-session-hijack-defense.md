セッションハイジャックの仕組みと、PHPでできる基本的な対策をまとめました。
ログイン機能を作り始めたPHPエンジニアの方に向けた内容です。

## 結論

セッションハイジャックを防ぐポイントは、次の3つです。

* セッションIDを見える場所に置かない
* ログイン後に `session_regenerate_id()` でセッションIDを再生成する
* Cookieに `HttpOnly` と `Secure` を付ける

## セッションハイジャックとは

WEBシステムにログインしたあとに、セッションIDを盗んで、ログインした本人になりすます行為です。
システムによっては、次のようなことをされてしまいます。

* 不正送金
* 不正購入

他人の運転免許で契約したり、他人のパスポートで海外で悪さをしたりするのと、似た犯罪です。
だからこそ、**自分の情報はしっかり守る**ことが大切になります。

### セッションとは？

アクセス開始から終了までの、一連の通信のことです。
たとえば、システムにログインして、検索して、データを登録したとします。
検索と登録という2つの処理を1回のアクセスで行っているので、1セッションとして数えます。

HTTP通信は状態を保持できません。
そこで、セッションという値を使って、状態を保持していると覚えておきましょう。

## 対策

鉄則は、**攻撃者にセッションIDを推測されないこと**です。

### 見える位置にセッションIDを置かない

まず最初に、セッションIDを見える位置に置かないでください。

* URLにセッションIDを含めない
* `hidden` にセッションIDを設定しない(やる人はいないと思いますが、念のため)

### ログイン後にセッションIDを書き換える

そのうえで、なりすましを防ぐために、ログイン後にセッションIDを書き換えます。

PHPでは、組み込み関数の `session_regenerate_id()` を使います。
この関数を使うと、使っているセッションIDを新しいものに書き換えられます。
ログイン処理の関数の最後で呼び出せば、セッションIDを安全に管理できます。

```php
echo session_id();          // ① 書き換え前
session_regenerate_id(true); // セッションIDを書き換え(古いセッションは削除)
echo session_id();          // ② 書き換え後
```

### CookieをHTTPSのみに限定する

セッションIDはCookieに保存される仕組みなので、Cookieの設定も重要です。
`Secure` を付けて、HTTPS通信でのみCookieを送るようにします。
あわせて `HttpOnly` を付けて、JavaScriptからCookieを読めないようにします。

Apacheでの設定方法です。

```apache
Header edit Set-Cookie ^(.*)$ $1;HttpOnly;Secure
```

`php.ini` での設定方法です。

```ini
session.cookie_httponly = 1
session.cookie_secure = 1
```

:::message
元の記事では `session.cookie_httponly` のみ記載していましたが、`Secure` 属性に対応するのは `session.cookie_secure` です。
HTTPS環境であれば、合わせて設定しておきましょう。
:::

## まとめ

* セッションハイジャックは、セッションIDを盗んでログイン者になりすます攻撃です。
* セッションIDをURLや `hidden` に含めないようにします。
* ログイン後は `session_regenerate_id()` でセッションIDを書き換えます。
* Cookieには `HttpOnly` と `Secure` を設定しましょう。
