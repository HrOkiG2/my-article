Javaのラムダ式の基本を、前提となるインターフェースの話から整理しました。
ラムダ式の目的や使いどころを知りたいJava学習者の方に向けた内容です。

## 結論

ラムダ式は、**記述を簡略化する**ための構文です。
関数型インターフェース(抽象メソッドが1つのインターフェース)の実装を、短く書けます。

## 前提知識: インターフェース

インターフェースとは、「クラスに含めるメソッドの具体的な処理は書かず、メソッドの型だけを定義したもの」です。
(分かる方は、飛ばしてください。)

たとえば、`Phone` というインターフェースを使って、`Call` クラスや `Mail` クラスを作ります。

```java
// インターフェース
interface Phone {
    void action();
}

// インターフェースを実装して、Callクラスを作る
class Call implements Phone {
    public void action() {
        System.out.println("電話をかけます");
    }
}

// インターフェースを実装して、Mailクラスを作る
class Mail implements Phone {
    public void action() {
        System.out.println("メールを送ります");
    }
}

public class Main {
    public static void main(String[] args) {
        Phone c = new Call();
        Phone m = new Mail();
        c.action(); // 電話をかけます
        m.action(); // メールを送ります
    }
}
```

イメージは、次のとおりです。

* インターフェースを「土台」として捉えます。
* その土台で定義されている、空のメソッドという「道具」を、
* 使える状態(実装)にしていきます。

抽象クラス(`abstract`)と似ていますが、抽象クラスは**1つしか継承できない**のに対して、インターフェースは**複数実装できます**。

## ラムダ式とは

### ラムダ式の目的

目的は、記述を簡略化することです。構文は次のとおりです。
引数を渡して、処理内容を書くだけで、普段のメソッドと変わりません。

```java
(引数) -> { 処理内容 }
```

### メソッドを変数のように扱う

1つ目の良い点は、メソッドを変数のように扱えることです。
インスタンス化するときに、メソッドをそのまま書くだけで使えます。

```java
interface Phone {
    String call(String name);
}

public class Main {
    public static void main(String[] args) {
        Phone p = (name) -> { return name + "へ電話をかけます"; };
        System.out.println(p.call("ビートルズ")); // ビートルズへ電話をかけます
    }
}
```

クラスを作らなくても、実装を渡せます。

### 関数型インターフェースを楽に書ける

Javaには、**関数型インターフェース**(抽象メソッドを1つだけ持つインターフェース)があります。
(抽象メソッドは、具体的な処理が書かれていないメソッドです。)

先ほどのように自分で作った関数型インターフェースのほか、`Consumer` や `Function` など、Javaが用意しているものもあります。
説明が長くなるので、次のサイトを見てください。とても分かりやすいです。

* https://www.yoheim.net/blog.php?q=20160410

## まとめ

* ラムダ式は、記述を簡略化する構文です。
* 関数型インターフェース(抽象メソッドが1つ)の実装を、短く書けます。
* メソッドを変数のように扱えるのが、便利なところです。
