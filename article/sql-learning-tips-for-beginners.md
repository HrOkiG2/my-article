SQLを学んで気づいたことを、就職、考え方、書き方の3つの面からまとめました。
SQLを学び始めた方や、どこから勉強すればいいか迷っている方に向けた内容です。

## 結論

* SQLは、インフラにもバックエンドにも役立つ、必須の技術です。
* SQLの実行順序(FROM → WHERE → …)を意識すると、意図したデータを取得できます。
* インデントをそろえて、予約語を大文字にするだけで、読みやすくなります。

## 就職編

### 結局SQL

SQLは、必要不可欠な技術です。
アプリケーションは、PHPやJavaなどの言語で作りますが、**データを扱える言語は、SQL**です。
そのため、SQLができるだけで重宝されます。

### インフラにもバックエンドにも

IT業界の職種は広いですが、SQLは、インフラとバックエンドの領域が重なっているので、就職の選択肢がかなり広がります。
最近は、フロントエンドの人もSQLを使うことがあるそうです。(友達の情報です。)

SQLを基盤に学べば、データを扱えるIT人材になれます。
どこを目指せばいいか分からない人は、まずSQLを学ぶのがよいと考えています。

## 考え方編

### 実行順序

SQLの実行順序の理解は、大切です。
順序が分かると、目的に沿ったSQLを書けます。逆に言うと、**実行順序を意識していないと、意図しないデータを取得してしまいます。**

実行順序は、次のとおりです。

1. `FROM`
2. `WHERE`
3. `GROUP BY`
4. `HAVING`
5. `SELECT`
6. `DISTINCT`
7. `ORDER BY`

学び始めた頃は、欲しいデータに意識が向いて、`SELECT` 句が重要だと考えていました。
ですが、本当に欲しいデータを取得するには、**元になるテーブルから考える**必要があります。
どのテーブルから、どの条件で、データを取得するのかを意識してみてください。

### 書き方は十人十色

早めに知りたかったのですが、**SQLの書き方は十人十色**です。
学び始めのころは、教科書どおりに書かなければと思って、柔軟性のないSQLを書いていました。
(教科書では、「`IN` は `EXISTS` で代替できる」「サブクエリはできるだけ書かない」などと言われます。)
ですが、実務では、「こういう書き方はよくない」と言われている書き方のSQLを、よく目にします。
(1万レコードを `UNION` で、横持ちのデータを縦持ちに結合している、びっくりするコードを見たこともあります。)

Aを取得するために、こうしたほうがよい、という書き方はありますが、正解は1つではありません。
**必要なデータを取得できないことが一番悪い**ので、慣れるまでは、速さやきれいさは気にしなくて大丈夫です。
知見が増えれば、自然と最適な書き方が分かってきます。

### データは超重要

「データより、画面を動かすほうが、ITっぽくてかっこいい」と思っていました。
ですが、実務に入って、**ビジネスに必要なのはデータ**だと気づきました。
データを、自分たちの使いやすい形で取得・加工して、お金を生み出す形で使っているのが、Webサービスの根幹だと思います。
データを扱えるのは、強いです。

## 書き方編

### インデントをそろえる

SQLの経験が浅くてもできる1つ目は、**インデントをそろえる**ことです。
次の2つを比べると、見やすさが全然違います。

```sql
-- インデントなし
SELECT no, name FROM test
WHERE no > 4
AND name IN ('aiueo', 'test')
ORDER BY no;

-- インデントあり
SELECT no, name
  FROM test
 WHERE no > 4
   AND name IN ('aiueo', 'test')
 ORDER BY no;
```

### 予約語は大文字にする

2つ目は、**予約語を大文字で書く**ことです。
予約語は、SQLで決められている単語です(`SELECT`、`FROM`、`WHERE`、`JOIN` など)。

```sql
-- 小文字
select no, name from test
where no > 4
    and name in ('aiueo', 'test')
order by no

-- 予約語を大文字
SELECT no, name
  FROM test
 WHERE no > 4
   AND name IN ('aiueo', 'test')
 ORDER BY no;
```

### 目的を考える

SQLに慣れてきたら、「何のデータが欲しいのか」を考える癖をつけましょう。
SQLは、さまざまな書き方でデータを取得できるので、目的を明確にして、必要なデータを取得することを意識してください。
目的が明確になると、どの書き方が最適かが、だんだん分かってきます。

## まとめ

* SQLは、就職の選択肢を広げてくれる、必須の技術です。
* 実行順序を意識して、元のテーブルから考えましょう。
* 書き方に正解は1つではなく、必要なデータを取得できることが大切です。
* インデントと予約語の大文字で、読みやすいSQLになります。
