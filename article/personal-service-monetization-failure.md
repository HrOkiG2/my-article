> 初出: 2024年1月27日(旧ブログの記事を移行・加筆)

個人開発で作ったサービスをマネタイズできず、6ヶ月で終了させた経緯と反省をまとめました。
個人開発で収益化を考えている方に、失敗例として参考にしてもらえればと思います。

## 結論

個人が作ったサービスは、技術がしっかりしていても、**知名度と実績がなければ売れません。**
作る前に、ターゲットと売り方を先に検証するべきでした。

## 作ったもの

HP 兼 予約サイト 兼 ECサイトのシステムです。
私は沖縄県の出身で、地元の小規模な個人経営のお店の営業を肩代わりすることを目的に作りました。

沖縄は観光地として有名なのに、HPすら持たず、地元の口コミだけで経営しているお店がたくさんあります。
せっかくの観光地なのにお客さんを呼び込めないのはもったいない、という思いがきっかけでした。

## 技術構成

| 項目 | 内容 |
| --- | --- |
| デザイン | Tailwind + DaisyUI |
| フロントエンド | React |
| バックエンド | Laravel 10 |
| DB | RDS(MySQL 8.x) |
| 決済 | Stripe |
| インフラ | サーバー: EC2 / DB: RDS / ファイルサーバー: S3 |
| その他 | Docker |

## マネタイズポイント

### 物販

沖縄ならではの商品を扱うEC機能です。
1商品ごとに、x%の手数料をいただく契約を想定していました。

### 予約

美容院やレジャー施設の予約を受け付ける機能です。
ECと同じく、1予約あたりx円の手数料か、オプション契約のどちらかを想定していました。

## 売り方

沖縄出身ですが、勤務地は都内なので、現地での営業活動ができませんでした。
そこで、地元の友人に営業を頼みました。「月100万円稼げるシステムを作るから、営業してほしい」と、**かなり大きく盛った話**をして依頼しました。

友人は面白そうだからと快く引き受けてくれて、次の方法で営業してくれました。

* SNS(Instagram、Twitter)
* ブログ

結論から言うと、6ヶ月間やって、**契約は1件も入りませんでした。**

## なぜ売れなかったのか

### 知名度がなかった

認知されていないサービスに、お金を払いたい人はいません。
ましてや、登記もしていない個人が作ったシステムに、大切なお金を払うのは考えにくいです。

考えられた手段は、次のとおりです。

* 正しい営業をする
* 受託などで知名度を得る
* ほかのサービスで知名度を得る(ただし、知名度がないことの無限ループになります)

お客さまが安心して投資できる、と胸を張って言える状態を作るのは、難しいです。

### 効果を得られるか不安だった

知名度の話に近いですが、このシステムで利益が出るという不安を、取り除けませんでした。
契約が1件もない、つまり実績がないので、お客さまにとっては不安しかありません。

世の中のスタートアップは、どうやって最初の利益を得ているのでしょうか。

### ターゲットの見立てが甘かった

確かなデータがあるわけではなく、あくまで私の印象ですが、ターゲットの価値観を見誤っていた可能性があります。

私が知っている沖縄の経営者(4人だけですが)は、「食べていける分を稼げて、楽しい毎日を送ることが大切」と考える人が多かったです。
そういう方に「業務を効率化して、売上を伸ばしましょう」と提案しても、「忙しくなるなら今のままでいい」という返事になりがちです。

事前にターゲットをしっかり調査するか、先に買ってくれそうな層を見つけることが大切だと感じました。

## 反省

誰にも使われないシステムは、価値を生みません。
今回は、自分と友人の時間が溶けただけで済んだので、まだよかったです。
(実際には、運用費として5万円ほど使いました。)

もし起業してサービスを作っていたら、廃業に大きく近づいていたと思います。
個人開発のうちに、ここまで学べたのは貴重な経験でした。

まだ作りたいものはたくさんあるので、引き続き頑張ります。

## まとめ

* 個人が作るサービスは、知名度と実績がないと、なかなか売れません。
* 作る前に、ターゲットの価値観と売り方を検証しましょう。
* 小さく始めて、早めに反応を確かめるのが大切です。
