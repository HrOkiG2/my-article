Webの基盤になっているHTTPとHTTPSの基本を、まとめました。
インターン生に「HTTPって何ですか?」と聞かれて、うまく説明できなかったことをきっかけに、学び直した内容です。

## 結論

HTTPは、WebブラウザとWebサーバーが通信するためのプロトコルで、**ステートレス**です。
HTTPSは、HTTPに、SSL/TLSによる**暗号化**を加えたものです。

## HTTPとは

HTTPは、WebブラウザとWebサーバーの間の通信を可能にするプロトコルです。
1990年代から、Webの成長とともに進化してきました。

HTTPは**ステートレス**なプロトコルで、過去のリクエストやレスポンスの状態を保持しません。
これにより、プロトコルのシンプルさと、拡張性が保たれています。(ステートレスについては、別記事「ステートフルとステートレスをざっくり理解する」を参照してください。)

## HTTPSとその重要性

HTTPSは、HTTPに**セキュリティ層**を加えたものです。
SSL(Secure Sockets Layer)、またはTLS(Transport Layer Security)で、クライアントとサーバー間の通信を暗号化します。

この暗号化で、データの**盗聴、改ざん、なりすまし**を防げます。
ECサイトやオンラインバンキングなど、機密性が求められる情報を扱うサイトでは、HTTPSが必須です。
SSLを知らないと、Web業界では恥をかくので、ご注意ください。(SSL化については、別記事「LAMP環境の構築における注意点」も参照してください。)

## HTTPメソッド

HTTPメソッドは、クライアントが、サーバーに何をしたいかを伝える手段です。
もっとも一般的なメソッドは、次のとおりです。

| メソッド | 用途 |
| --- | --- |
| `GET` | リソースを取得します。 |
| `POST` | リソースを作成します。 |
| `PUT` | リソースを更新します。 |
| `DELETE` | リソースを削除します。 |

これらのメソッドは、RESTful APIの設計で、重要な役割を果たします。

## ステータスコード

HTTPステータスコードは、サーバーが、クライアントのリクエストをどう処理したかを示します。
よく使われるものは、次のとおりです。

| コード | 意味 |
| --- | --- |
| `200 OK` | リクエストが成功しました。 |
| `404 Not Found` | リクエストされたリソースが、見つかりませんでした。 |
| `500 Internal Server Error` | サーバー側で、問題が発生しました。 |

これらのコードは、デバッグやエラー処理で、とても役立ちます。

## ヘッダーとCookie

HTTPヘッダーは、リクエストやレスポンスの**メタデータ**を提供します。
たとえば、`Content-Type` ヘッダーはリソースの種類を示し、`Set-Cookie` ヘッダーは、クライアントにCookieを設定するよう指示します。

Cookieは、サーバーが、クライアントのブラウザにデータを保存するために使う、小さなデータです。
これによって、セッション管理、パーソナライズ、トラッキングなどができます。

## まとめ

* HTTPは、ステートレスなプロトコルです。
* HTTPSは、SSL/TLSで通信を暗号化して、盗聴、改ざん、なりすましを防ぎます。
* メソッド、ステータスコード、ヘッダー、Cookieの理解は、Web開発の基本です。
