AWS Route 53の概要と主な機能、特にルーティングポリシーの違いをまとめました。
Route 53を使い始めた方や、ルーティングポリシーの使い分けに迷っている方に向けた内容です。

## 結論

Route 53は、**ドメイン登録、DNSルーティング、ヘルスチェック**を提供する、高可用なDNSサービスです。
ルーティングポリシーを使い分けると、ユーザー体験の向上や、高可用性を実現できます。

## Route 53の概要

Route 53は、Webアプリケーションやサービスの可用性を高めるために設計された、DNSサービスです。
次の3つの主要な機能があります。

1. **ドメイン登録**: ドメイン名の登録、管理ができます。Route 53で購入したドメインは、AWSの他のサービスと簡単に統合できます。
2. **DNSルーティング**: ドメイン名を、特定のリソース(IPアドレス、ロードバランサー、S3バケットなど)にルーティングします。グローバルなDNSネットワークで、低遅延かつ信頼性の高いルーティングができます。
3. **ヘルスチェックと監視**: 障害が起きたリソースを自動で切り離して、代替リソースに切り替えます。

## Route 53の主な機能

### ドメイン管理

* ドメインの購入、更新、移管を簡単にできます。
* AWS CLIやAPIで、プログラムからも管理できます。

### 可用性の高いDNS

* 低遅延の名前解決を提供する、グローバルに分散したDNSネットワークです。
* SLAで、100%の可用性が保証されています。

### セキュリティ

* DNSSEC(Domain Name System Security Extensions)に対応していて、DNSの改ざんを防止できます。
* IAMポリシーで、Route 53リソースへのアクセスを制御できます。

## Route 53のルーティングポリシー

ルーティングポリシーは、DNSクエリに対して、どのリソースを選ぶかを定義します。

### シンプルルーティング

最も基本的なポリシーです。1つのドメイン名に、1つのIPアドレスまたはエンドポイントを割り当てます。

* **用途**: 単一のリソースにトラフィックを送る場合
* **例**: `www.example.com` が、特定のEC2にルーティングされる設定

### 加重ルーティング

トラフィックを、複数のリソースに、指定した比率で分散します。

* **用途**: A/Bテストや、異なるリソース間の負荷分散
* **設定項目**: 各リソースにウェイト(数値)を割り当てます。ウェイトの合計に対する比率で、トラフィックが分かれます。

### レイテンシールーティング

ユーザーのリクエストを、最もレイテンシーが低いリージョンのリソースにルーティングします。

* **用途**: ユーザー体験を向上させるために、最適なリージョンにトラフィックを送る場合
* **動作**: AWSのグローバルインフラに基づいて、最適なリージョンを自動で選びます。

### フェイルオーバールーティング

プライマリのリソースが使えないときに、セカンダリのリソースにトラフィックを送ります。

* **用途**: 災害復旧や、高可用性システムの構築
* **要件**: ヘルスチェックの設定が必要です。

### 地理的ルーティング

ユーザーの地理的な位置に基づいて、特定のリソースにトラフィックを送ります。

* **用途**: 地域ごとに、異なるコンテンツを提供する場合
* **設定項目**: 大陸、国、州などの地域を指定します。

### 地理的近接性ルーティング

地理的に最も近いリソースに、トラフィックを送ります。

* **用途**: リージョンごとに最適化されたサービスを提供する場合
* **特徴**: 特定のリソースにトラフィックを優先的に送る「バイアス」を設定できます。

### マルチバリュールーティング

複数のリソースを返すことで、DNSクライアント側で負荷分散できるようにします。

* **用途**: 高可用性のために、複数のIPを返したい場合
* **設定項目**: ヘルスチェックに合格したリソースだけを返す設定ができます。

### 地理的ルーティングと地理的近接性ルーティングの違い

| 項目 | 地理的ルーティング | 地理的近接性ルーティング |
| --- | --- | --- |
| ルーティング基準 | ユーザーの地理的な場所(国、州、地域)で、特定のリソースにルーティングします。 | ユーザーとリソースの地理的な距離を考慮して、最も近いリソースにルーティングします。 |
| 適用範囲 | 指定した国や地域に、明確にルーティングします。 | 距離と近接性に基づいて、動的にルーティングします。 |
| 設定項目 | 国や地域ごとに、ルーティング先のリソースを指定します。 | 距離の近さを考慮しつつ、特定のリソースを優先する「バイアス」を設定できます。 |
| 具体例 | 日本のユーザーは東京リージョン、アメリカのユーザーはオレゴンリージョン | 東京に近いユーザーは東京リージョン、ソウルに近いユーザーはソウルリージョン |
| 主な用途 | 地域ごとに異なるコンテンツやサービスを提供する場合 | 地理的な近さで、パフォーマンスを最適化する場合 |
| 動作イメージ | 固定的で、明示的なルール | 動的で、距離に基づくルール |

## まとめ

* Route 53は、ドメイン登録、DNSルーティング、ヘルスチェックを提供します。
* ルーティングポリシーは、用途(分散、レイテンシー、障害時の切り替え、地域別など)で選びます。
* 地理的ルーティングは「明示的な地域指定」、地理的近接性は「距離に基づく動的な選択」です。
