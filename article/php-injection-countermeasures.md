PHPで気をつけたいインジェクション攻撃のうち、SQLインジェクションとコマンドインジェクションの基本と対策をまとめました。
PHPでフォーム入力を扱い始めた方に向けた内容です。

## 結論

* SQLインジェクションは、PDOの **プレースホルダ** で防ぎます。
* コマンドインジェクションは、そもそも外部入力をOSコマンドに渡さないのが基本です。

## SQLインジェクション

### 起こりうる脅威

IPAの「[安全なウェブサイトの作り方 改訂第７版](https://www.ipa.go.jp/files/000017316.pdf)」では、次の脅威が挙げられています。

* データベースに蓄積された非公開情報の閲覧
  * 個人情報の漏えいなど
* データベースに蓄積された情報の改ざん・消去
  * ウェブページの改ざん、パスワード変更、システム停止など
* 認証回避による不正ログイン
  * ログインした利用者に許可されている、すべての操作を不正に行われます
* ストアドプロシージャ等を利用したOSコマンドの実行
  * システムの乗っ取りや、他への攻撃の踏み台としての悪用など

### PHPでの対策: プレースホルダを使う

フォームの入力値を、直接SQL文に埋め込まないようにしましょう。
代わりに、プレースホルダを使って値をバインドします。

プレースホルダには2パターンあります。
ただし、**同じSQL文の中で両方を混ぜて使うことはできません。**
個人的には、名前付きプレースホルダのほうが分かりやすくておすすめです。

```php
// 疑問符パラメータ
$stmt = $pdo->prepare('SELECT * FROM test WHERE id = ? AND input_date = ?');

$stmt->bindValue(1, '100');
$stmt->bindValue(2, '2022-08-01');

$stmt->execute();

// 名前付きプレースホルダ
$stmt = $pdo->prepare('SELECT * FROM test WHERE id = :id AND input_date = :input_date');

$stmt->bindValue(':id', '100');
$stmt->bindValue(':input_date', '2022-08-01');

$stmt->execute();
```

## コマンドインジェクション

外部から入力された値に悪意のあるコマンドを仕込み、サーバー上で実行させる攻撃です。

### 起こりうる脅威

こちらもIPAの資料から引用します。

* サーバー内ファイルの閲覧・改ざん・削除
  * 重要情報の漏えい、設定ファイルの改ざんなど
* 不正なシステム操作
  * 意図しないOSのシャットダウン、ユーザーアカウントの追加・変更など
* 不正なプログラムのダウンロード・実行
  * ウイルス、ワーム、ボットなどへの感染、バックドアの設置など
* 他のシステムへの攻撃の踏み台

### PHPでの対策

元の記事では対策が未記載だったため、基本的な考え方を補足します。

* `exec()` や `system()` など、OSコマンドを実行する関数は、できるだけ使わないようにします。
* どうしても使う場合は、外部入力をそのまま渡さず、`escapeshellarg()` でエスケープします。
* 可能なら、許可する値をホワイトリストで限定します。

```php
// 例: 外部入力をエスケープしてから渡す
$arg = escapeshellarg($_GET['name']);
$result = shell_exec('ls ' . $arg);
```

## まとめ

* SQLインジェクションは、プレースホルダ(バインド)で防ぎます。
* プレースホルダは「疑問符」と「名前付き」の2種類があり、混在はできません。
* コマンドインジェクションは、外部入力をOSコマンドに渡さないことが一番の対策です。
* どうしても渡す場合は `escapeshellarg()` とホワイトリストで守りましょう。
