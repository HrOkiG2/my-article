AWSでの負荷分散の基礎として、クロスリージョン構成、起動テンプレート、Auto Scalingのポリシーをまとめました。
EC2を使った、可用性の高い構成を検討している方に向けた内容です。

## 結論

* クロスリージョンは、Global AcceleratorやRoute 53で、トラフィックを振り分けます。
* EC2の構成は、起動テンプレートでバージョン管理します。
* Auto Scalingは、用途に合ったスケーリングポリシーを選びます。

## クロスリージョン

複数のアーキテクチャがあり、予算によるところが大きいです。
いずれも、RDSやS3のクロスリージョンレプリケーションを組み合わせて、リージョン間でデータを同期する必要があります。

### AWS Global Accelerator

* グローバルIPを提供して、異なるリージョンのアプリケーションにトラフィックを分散するサービスです。
* **最適なエッジロケーション**を使って、ユーザーに近いリージョンにルーティングするので、遅延が少なくなります。

### Route 53のDNSベースのルーティング

リージョンごとに、トラフィックを制御できます。

* **レイテンシールーティング**: ユーザーから最も近い(レイテンシーが低い)リージョンに誘導します。
* **地理的ルーティング**: ユーザーの地理的な場所に基づいて、特定のリージョンに送ります。
* **フェイルオーバールーティング**: 特定のリージョンが使えなくなったら、他のリージョンに切り替えます。

### Route 53 + ALB

* **各リージョン**にALB(Application Load Balancer)を置いて、**Route 53**で各ALBを管理します。
* リージョンごとに複数のアプリケーションを動かして、DNSルーティングで最適なリージョンに誘導します。

## 起動テンプレート

### 設定できるオプション

* **AMI(Amazon Machine Image)**: 起動するインスタンスの、OSやアプリケーションを含むイメージです。
* **インスタンスタイプ**: CPU、メモリなどの仕様です(例: `t3.micro`、`m5.large`)。
* **キーペア**: インスタンスにSSHでアクセスするための、公開鍵情報です。
* **セキュリティグループ**: インスタンスへのトラフィックを制御する、ファイアウォールです。
* **IAMロール**: インスタンスに割り当てるIAMロールです(S3やCloudWatchなどへのアクセスに使います)。
* **ストレージ設定**: EBSボリュームのサイズ、タイプ、スナップショットです。
* **ネットワーク設定**: VPC、サブネット、ネットワークインターフェースの設定です。

起動テンプレートは、**バージョニング**もできます。

## スケーリングポリシー

### 動的スケーリング

* **シンプルスケーリング**: 1つのイベントが起きると、**固定の数**のインスタンスを増減します。
* **ステップスケーリング**: メトリクスの変化に応じて、**段階的**に増減します。たとえば、CPU使用率が70%を超えたら2台追加、90%を超えたら3台追加します。
* **ターゲット追跡スケーリング**: 特定のメトリクスの目標値を決めて、そこから外れたら、自動で追加・削除します。

### そのほかのスケーリング

* **スケジュールに基づくスケーリング**: 指定した日時に1回だけ、または定期的なスケジュールでスケーリングします。
* **予測スケーリング**: 過去のパフォーマンスデータから、将来の需要を予測して、最適な台数にします。バッチのようなイメージです。
* **手動スケーリング**: ユーザーが、任意のタイミングでスケーリングします。

## ライフサイクルフック

ライフサイクルフックを使うと、EC2の**起動**や**終了**のプロセスに、一時停止(wait状態)を追加できます。
その間に、スクリプトや他のAWSサービスと連携した処理を実行できます。

**主なユースケース**

* **起動時**: 初期設定や、アプリケーションのセットアップ
* **終了時**: セッションデータの保存、ログの転送、クリーンアップ

## スケールインの終了ポリシー

**スケールイン終了ポリシー(Termination Policy)**は、Auto Scalingグループでインスタンスを減らすときに、**どのインスタンスを終了するかを決めるルール**です。

### デフォルトの終了ポリシー

次の順番で判断されます。

1. **AZのバランスを維持**: インスタンス数が多いAZから終了します。
2. **スポットインスタンスを優先**: スポットとオンデマンドが混在していれば、スポットを優先的に終了します。
3. **起動テンプレートのバージョン**: 古いバージョンのインスタンスを優先して終了します。
4. **最も古い起動時間**: 他の条件が同じなら、最も古く起動したインスタンスを終了します。

### スケールイン設計の考慮事項

* **最小インスタンス数(`MinSize`)**: これを下回らないように、終了されます。
* **AZの均等分散**: 終了時も、複数のAZのバランスが保たれるように設計されています。
* **ヘルスチェックとの連携**: ヘルスチェックで「異常」と判断されたインスタンスは、終了ポリシーにかかわらず、優先的に終了されます。

## まとめ

* クロスリージョンの負荷分散は、Global AcceleratorやRoute 53を使います。
* 起動テンプレートで、EC2の設定をバージョン管理できます。
* スケーリングポリシーは、動的・スケジュール・予測・手動から選びます。
* ライフサイクルフックと終了ポリシーで、起動・終了時の動きを制御できます。
